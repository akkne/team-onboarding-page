# Стиль кода

## Общие правила

- Пиши короткий, понятный код без очевидных комментариев, заглушек и неиспользуемых файлов.
- Называй сущности по предметной области проекта.
- Держи секреты и локальные значения вне кода, в неотслеживаемом `.env`. После появления приложений перечисли нужные переменные в `.env.example`. Публичные переменные Next.js не должны содержать секреты.
- При изменении поведения обновляй документацию и проверяй затронутый сценарий.
- Указывай типы на публичных границах. Применяй согласованные форматтер и линтер.
- Обрабатывай ошибки явно. Сохраняй контекст ошибки и возвращай понятный результат.
- Новые тесты размещай в `tests/`. Проверяй изменённый сценарий и ошибки через его публичный контракт.

## Next.js и Tailwind CSS

- Для каждого пользовательского текста указывай русский и английский варианты. Используй общий механизм перевода на клиенте и сервере. Проверяй также пустые состояния, загрузку, ошибки, подсказки и aria-подписи. Отделяй переводимые подписи от пользовательских данных.
- Используй TypeScript для нового интерфейса. Компоненты делай небольшими и называй по назначению.
- Все экраны и компоненты в `frontend/` оформляй утилитами Tailwind CSS 4 в `className`. Для адаптивной вёрстки, фокуса, выбора и отключённых элементов используй варианты Tailwind. В условиях указывай полные имена классов, чтобы сборщик мог их обнаружить.
- Цвета и тени обеих тем задавай в общей таблице стилей и подключай через `@theme inline`. Следуй [дизайн-системе](design-system.md). Повторяющиеся наборы утилит для кнопок, полей и панелей вынеси в общие стили.
- Для значения, которое становится известно только при рендеринге, передавай данные через CSS-переменную и применяй её в статической утилите Tailwind.
- Учитывай доступность: семантическая разметка, подписи полей, управление с клавиатуры, видимый фокус и состояния загрузки/ошибки.
